# 디자인 가이드 — LearnUs v2

> 기획 5단계 "화면 기획"(발표자료 부록 B5 화면별 요소 분석표)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 순서로 같이 고칩니다.

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 학사 일정·과제 목록 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/items` |
| B | 과제·공지 상세 안내 | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A에서 카드 누름 | `/notes?itemId=` ('과제 메모' 탭) |
| C | 과제 제출 체크리스트(임의) | `lib/screens/c_result_sheet.dart` | 덮기(modal) — B의 "제출 양식 및 제출함 열기" | 없음(미리 정한 결과) |

```
A 목록 ──쌓기(push)──▶ B 상세 [옆으로(tab): 과제 안내 | 과제 메모] ──덮기(modal)──▶ C 체크리스트(임의)
A 목록 ──덮기(dialog)──▶ A-7 긴급 표시 기준 안내창
```

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(tab) · **덮기**(modal · dialog)
- 적응형: A는 창 너비 **600dp 이상**이면 격자(GridView), 미만이면 목록(ListView) — `LayoutBuilder`.
- A-7 안내창은 새 화면이 아니라 A 위에 덮는 작은 창입니다.

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### AI 2문장 요약 (B-3)
- **목적**: 긴 공지를 끝까지 읽지 않아도 요지를 알게 한다.
- **내용**: AI가 만든 두 문장 요약과 "AI가 요약한 내용입니다. 정확한 내용은 아래 상세 안내문을 확인하세요." 문구.
- **의도**: P08(핵심 먼저) · P01(AI가 만든 글임을 표시) · 현행 앱은 안내문 전체가 이어져 핵심을 찾으려면 스크롤해야 함(직접 관찰) · 리뷰 ★1 · 2025-03-18 "학점과 직결되는 문제들인데 앱만 믿었다간 학점에 흠결이 갈 수 있습니다"

### 과제·공지 카드 목록 — 긴급 표시 (A-2)
- **목적**: 긴급 공지와 일반 과제를 목록에서 바로 구분한다.
- **내용**: 긴급 항목만 빨간 카드, "긴급" 뱃지, 경고 아이콘. 나머지는 흰 카드와 D-일수 뱃지.
- **의도**: P01 · 색만이 아니라 아이콘과 글자도 함께 써서 색에 의존하지 않는다 · 현행 앱은 긴급·일반 항목이 같은 모양(직접 관찰) · 리뷰 ★1 · 2023-06-14 "푸시알림안오고 … 과제 기한 못맞춤"

### 긴급 표시 기준 도움말 (A-7)
- **목적**: "긴급"이 무엇을 뜻하는지 화면에서 바로 알려 준다.
- **내용**: 앱바 "?" 아이콘을 누르면 "휴강, 마감 변경처럼 지금 바로 확인해야 하는 공지에 '긴급'이 붙습니다."라는 안내창이 뜬다.
- **의도**: P10 · 도움말이 필요한 곳 가까이에 둔다 · 셀프 논증 쟁점 2에서 나온 내 반론("기준이 설명되지 않음")에 대한 수정.

### 오류 안내·다시 시도 (A-5)
- **목적**: 목록을 못 불러왔을 때 무엇이 잘못됐고 어떻게 복구하는지 알린다.
- **내용**: 오류 문장, 서버 주소, "다시 시도" 버튼 1개.
- **의도**: P09 · 사라지는 알림이 아니라 화면에 남는 버튼으로 복구 경로를 준다.

### 제출 체크리스트 시트 (C-1)
- **목적**: 제출 전에 확인할 항목을 현재 화면을 떠나지 않고 보여 준다.
- **내용**: 번호가 있는 항목 3개, 예시 안내 문구, "닫기" 버튼.
- **의도**: P03 · 공지가 뒤에 보이는 채로 쉽게 닫는다 · P07 · 버튼 한 번으로 열기.
